# Agent Chat

Agent Chat 是 Scribe 的桌面聊天工作区。Scribe 直接在 Obsidian 内运行自己的代理，沿用你已配置的模型、密钥和连接地址。开始聊天不需要安装或登录外部代理程序。

Quick Ask、Quick Command 继续用于编辑器旁的简短提问和改写，也保留移动端入口。

## Set up Scribe

1. 打开 **Settings → Scribe → 模型**，添加供应商或本机模型，并填写它需要的连接信息。
2. 配置完成且连接可用的模型可直接用于聊天，无需另外启用。可在聊天输入框旁选择模型、推理强度和权限模式。
3. 点击 Agent Chat 图标，或运行 **打开 Scribe 代理聊天窗口**，输入任务。

新聊天记住上次成功选择的模型、推理强度和权限模式。首次使用默认选择配置顺序中的第一个可运行模型，权限模式默认为自动模式；恢复旧聊天时保留该聊天自己的选择。没有可用模型时，请在“模型”页检查服务商连接和凭证；不同设备的密钥不会自动共享。

## Models, effort, and permissions

输入框旁的模型选择用于当前聊天，并记住为之后新聊天的选择。推理强度按模型支持的选项显示；更改后在下一次请求中使用。具体支持情况和费用由你的模型服务决定。

| 模式        | 行为                                                                                 |
| ----------- | ------------------------------------------------------------------------------------ |
| **Default** | 可以读取和搜索笔记；写入笔记、修改绘图和执行系统命令通常需要批准。                   |
| **Plan**    | 保持计划模式时阻止编辑和系统命令；可以审阅、拒绝计划或附反馈退回修改。               |
| **Auto**    | 通常自动允许资料库内普通笔记及绘图编辑；资料库配置目录中的编辑和系统命令不自动放行。 |

权限卡显示具体操作、发起者、命令或文件信息。编辑和命令可选择在当前聊天中始终允许或始终拒绝相同操作；已保存的决定会先于 Auto 的自动放行规则生效，因此系统命令不一定每次都弹卡。其他请求以卡片实际提供的选项为准。**Stop** 取消当前回复及其尚未回答的请求。

批准计划后，当前聊天会切回 **Default**。你也可以手动切换模式，后续操作按所选模式和已保存的授权执行。手动在聊天中切换权限模式，还会更新之后打开聊天时使用的默认模式；批准计划后的自动切换不会更改这个默认值。

提问卡支持多题导航、选项和自行填写。提交后，答案回到提出这组问题的工具；取消会结束这次等待。

笔记工具原本限定在当前资料库内，但隔离测试发现：如果文件夹在检查后、写入前被替换，写入可能覆盖资料库外的文件；如果资料库内外的两个文件入口指向同一份文件，正常写入也会同时改动库外内容。系统拒绝写入时，原笔记也可能受损，或留下不完整的新文件。修复前，请暂时不要让代理写入或编辑笔记，包括使用 **Auto** 或已记住的授权；需要修改时，请先确认文件未与库外文件共用，再手动编辑，不确定时先另存为新笔记。经批准的系统命令使用你的电脑权限，可能访问资料库以外的文件或服务。

Note tools are intended to stay inside the current vault. Isolated tests found that replacing a folder after the check but before a write can overwrite an outside file. A normal write can also change an outside file when the vault entry and outside entry refer to the same file. If the system refuses a write, an existing note can be damaged or a new file left incomplete. Until this is fixed, do not ask the agent to write or edit notes, including through **Auto** or saved permissions. Before editing manually, confirm that the note does not share a file with an outside entry; if unsure, first save its contents as a new note. Approved system commands use your computer's permissions and may access files or services outside the vault.

## Context and history

打开的聊天分别保留自己的草稿、待发送附件和排队消息；切换聊天不会把另一条聊天的问题或草稿带进来。尚未点击发送的草稿和附件只保存在运行中的内存里，退出后不能依靠历史记录找回。已被接收的消息会先保存，包括排队等待的消息；重新打开历史不会自动把它们重新发送。请先另存需要保留的未发送文字，并保留附件原件。

- 通过原输入区添加笔记、编辑器选区、网页、图片和其他支持的附件；输入 `@` 或 `[[` 选择笔记。
- 项目保留自己的说明、上下文和聊天列表。当前资料库的个人技能可在不同项目中复用。
- **最近聊天** 和 **聊天历史** 保留查找、重命名、分叉、置顶、复制链接、书签和删除入口。聊天仍保存在当前资料库的 `.scribe` 内，每次只追加新发生的内容；复制链接、加入书签和置顶都不会创建笔记。确认删除聊天会删除该聊天的新记录和显示缓存，保留原有聊天笔记、共享图片和普通笔记。
- 消息下面可以复制正文、在编辑器光标处插入或替换，以及从该处建立新的聊天分支。
- 本次聊天格式改造前创建的聊天不再读取、显示或迁移，包括原先保存在 `.scribe` 内的聊天；旧文件原样保留，不会自动修改或删除。新建聊天从新格式开始。
- 重新打开新格式聊天时，Scribe 从保存的记录恢复内容；显示缓存可以重建。过往工具活动只回放显示，不会重新执行命令或改写文件。中断的任务不会自动重启。
- 图片按实际内容共享保存，相同图片在多条聊天中只占一份。删除一条聊天不会自动清理共享图片；图片缺失时会显示提示，原消息仍保留。

接收用户消息、工具获准即将执行，以及工具返回结果时，Scribe 会等待硬盘确认保存，再继续相应操作。保存失败时会停止新请求和尚未开始的操作。突然断电后，最近一次确认之后、尚未确认写入的内容仍可能丢失；这不是对所有正在显示的文字作出断电保留保证。

恢复时补充的信息会标注为“系统恢复说明”。“未启动”表示没有执行记录；“结果未知”表示操作已获准，但未保存结果，文件可能已经改变。请先核查对应文件和任务，再决定是否重试，不能把“没有结果”当作“没有改动”。

记录部分损坏时，仍会尽量显示可以读取的内容；如果无法确定后续内容的安全顺序，聊天只能查看，不能继续执行任务。保留原件及备份，可另开新聊天继续。

回复支持显示 Markdown、代码块和供应商实际提供的可展示思考内容。是否逐步显示取决于连接方式；使用缓冲连接时，内容通常在响应完成后显示。长聊天先显示最近 30 轮，点击 **再加载前 30 轮** 查看更早内容，完整记录仍然保存。已完成回合的工具和思考过程默认收起，点击摘要可展开；正在进行的回合保持展开，最终回复和需要处理的提示仍然可见。向上滚动时不会强制跳回最新位置；使用原来的向下按钮可继续跟随。

上下文环显示模型实际返回的用量；没有数据时保持缺数状态。这里不再显示外部代理账户的订阅额度。

### Fork a conversation

在一条已完成的回复下选择 **分叉对话**，可从该位置建立独立的新聊天。原来的聊天和任务保留。保存的工具活动作为历史显示，分叉不会复制执行它们。

### Compact a long chat

在输入开头选择 **/compact**，可让当前模型总结较长的聊天。模型窗口已知时，Scribe 在每次请求前检查上下文，包括同一条消息执行很多步骤的过程中；接近窗口的 80% 或需要为输出预留空间时，会尝试自动压缩较早内容。当前要求和最近完整的工具调用及结果仍保留。

聊天会显示压缩进行、完成、失败、取消或无需压缩的状态，并可展开查看已保存的摘要。压缩只改变模型请求采用的上下文：模型使用摘要和保留的原文，聊天里的完整原文始终保留，可继续向前查看。再次压缩从原文整理，不反复概括旧摘要。

摘要被截断、拒绝或无法安全容纳时停止本轮，保留原记录。窗口未知时无法提前按窗口比例压缩；明确收到上下文超限错误时仍会停止并提示。

### When a reply stops early

每轮步数默认无限制。可在 **Agent 配置 → 常规** 中明确选择限制并填写正整数；已经保存的上限继续生效。达到上限时，已执行的工具结果会交给模型，再进行一次不允许调用工具的收尾，总结完成事项、剩余工作及继续方式。若收尾仍要求工具调用，该调用不会执行。子代理也会收尾，并把达到上限的原因和实际总结交回父聊天。

步数上限、服务额度不足、身份验证失败、上下文问题、请求失败和主动取消分别显示原因。额度不足会立即停止，不再自动重试；这是服务账户限制，不是代码错误，补充额度或重新打开会话后可发送新消息继续。只有明确的临时故障才有限重试；已经显示部分回答或工具调用后，不自动重放整个请求。

错误分类依据服务商返回的结构化信息。若兼容服务只返回一段文字，或只给出无法区分额度和限流的状态，Scribe 会显示普通请求失败并停止自动重试，不猜测原因。自动停止后，尚未读取的排队内容会保留供你再次发送；已完成的操作不会回滚。

## While the agent works

### Send a message

可以在代理工作时继续输入。发送的排队消息会先保存，再等待代理下一步读取；**撤回排队消息** 将尚未读取的内容及附件放回输入框。**立即发送** 会停止当前回复，再立即处理等待消息。

### Background subagents and commands

Scribe 可以委派真实子代理，也能执行前台或后台系统命令。每个任务有自己的身份、输出和状态。子代理在独立上下文中工作，将结果交回父聊天，并使用对应的权限请求。

打开输入区上方的任务入口，可以查看子代理详情、后台命令的真实输出尾部、截断提示及成功、失败或停止状态。关闭详情仅关闭视图。**停止任务** 停止指定任务；其他任务继续运行。主回复结束后，后台任务仍可单独保持运行。

## Review what a turn changed

工具活动保留原有的读取、搜索、编辑、命令、网页和技能卡片。展开后可查看真实参数、路径和结果，并从原入口打开笔记。

写入或编辑后，变更摘要显示实际文件数和修改前后的差异。拒绝执行的操作不会被列成已写入。绘图在已发生部分修改后失败时，也保留实际变更。

## Skills

在 **Settings → Scribe → 技能** 管理当前资料库中的全部技能。点击“添加技能”，可选择 **Agent 创建、系统搜索、本地导入**：

- **Agent 创建**：用日常语言描述方法或流程。打开的聊天会自动带上内置 skill-creator 技能的调用（与技能列表“立即使用”一致）；如果该技能已停用，会先询问是否启用，已卸载时会提示先恢复内置技能。Agent 提供完整草稿，你可修改名称、说明、作者、版本、标签和正文；只有你点击“保存”后才安装。保存开始前取消或关闭确认窗口不会安装技能；保存期间关闭会尝试取消尚未提交的写入，已经完成提交时会按实际结果报告保存成功。
- **系统搜索**：按需查找电脑上支持的其他工具技能位置，显示名称、说明、来源与冲突状态。可逐项或批量导入，原来的技能文件始终保持不变。
- **本地导入**：在弹窗中直接拖放技能文件夹、ZIP 压缩包或单个技能 Markdown 文件，也可以点击拖放区或下方按钮打开文件选择；检查预览后导入，可识别压缩包或文件夹内的单层技能目录。单个 `.md` 文件需以合规的元数据块开头，文件名推导技能名（遵循同一命名规范与冲突规则），入库时展开为标准技能目录。每个技能最多 2000 个文件、50 MB。不安全的路径、文件链接、无效格式和跨来源同名会被拒绝。

导入的技能若存在轻微格式问题（如描述值含冒号未加引号、开关字段写成 yes/no 等），导入流程会自动尝试受限修复，并在确认窗口逐行展示“修改了什么”；只有你确认后才安装修复后的副本，原始来源文件永不修改。无法自动修复的技能维持拒收，可从详情页发起 Agent 修复。

所有技能和附带资源都保存在当前库 `.scribe/skills`。导入得到独立副本，原始来源后续变化不会自动同步；从相同来源重新导入需确认替换，副本中的修改也会被覆盖。名称会统一为小写英文、数字和连字符，最长 64 个字符，导入前可查看最终名称。已有无来源标识的技能显示为“本地”，继续可用；直接放入合规文件夹后，刷新或重新打开设置即可读取。不会扫描项目工作文件夹或创建技能链接，也不会自动读取、搬移或清理旧位置资料。

每行右侧依次是“立即使用”、启用开关、三点菜单（只有“卸载”）。点击名称或说明在设置页内进入详情页，返回按钮回到列表。详情顶部显示名称、版本、来源和全局启用状态；左侧“源文件”列出描述文件及支持文件，右侧查看所选文件。非内置技能可切换“预览/编辑”，直接编辑完整文件，包括描述文件中的全部元数据和正文；编辑会自动保存，切换文件或返回前等待保存完成，冲突时保留草稿并可重试或重新载入。切换到 Obsidian 的其他设置后再打开同一技能，可继续未保存的修改；重启插件前请等到“已保存”。Agent 创建确认仍须明确点击保存。内置技能只读。改名同时更新技能文件夹，保存时检查重名和外部修改。立即使用只打开引用技能的聊天草稿，不自动执行任务；已停用的技能会先询问是否启用。关闭开关会保留文件，卸载则删除库内技能及全部附带文件。格式有误的个人技能可从详情页让 Agent 修复。

Scribe 随插件附带 **skill-creator、defuddle、json-canvas、knap、obsidian-bases、obsidian-cli、obsidian-markdown** 七项技能，首次安装默认启用。内置技能在应用中只读，可停用、卸载，也可通过“恢复内置技能”找回；明确卸载的项目不会在重启或升级后自动恢复。升级遇到已有同名个人技能时跳过，不覆盖；内置文件在应用外修改过时保留现有内容，用户可选择保持原样或确认重置。内置技能的许可证、固定版本和来源说明随技能一起保存。

安装技能不会安装外部程序或执行附带脚本。Defuddle、Knap、Obsidian CLI 等能力需要按技能说明准备对应工具。skill-creator 的基础撰写使用 Scribe 会话；Claude 专用评估脚本不会从 Scribe 自动运行。只有明确要求评估时才生成工作资料，并保存在当前库技能目录的内部工作区中。
技能导入和编辑只修改指定内容，未修改的元数据保留原文，包括高精度数字和原有字段形式。已在独立 macOS 测试库核对真实导入、保存、重载和取消；这些结果不代表 Windows 或实体移动设备已经实机验证。

Skill imports and edits preserve untouched metadata text, including high-precision numbers and existing field representations. Import, save, reload, and cancellation were verified in an isolated macOS vault; Windows and physical mobile devices were not verified.

在聊天中输入 `/` 选择允许手动调用的技能，或使用内置的 `/compact` 压缩聊天。选中后，命令在输入框中显示为一个带类型图标和高亮背景的命令标签（只显示命令名）；实际发送的文本仍是 `/命令名`，模型看到的内容不变。通过“立即使用”或 Agent 创建等方式带入的命令草稿同样显示为该标签。模型也可以调用已注册且允许自动调用的技能。[Scribe 命令](custom-commands.md)从编辑器或 Obsidian 命令面板运行，不在当前代理聊天中展开。

模型看到的技能清单随每轮请求重建并声明“旧清单作废”，清单受上下文预算约束：默认不超过当前模型上下文窗口的 2%，且绝对不超过 10000 token，两项均可在技能页的“技能目录预算”中调整。超出预算时先移除占用空间最大的条目，极端情况下只保留技能名；设置页会显示当前预算状态和未进入模型可见列表的技能名。被移出清单的技能仍可被模型通过无参数调用技能工具列举获知。技能正文与支持文件的读取共用统一的大小上限，超限内容会被截断并明确标注。

技能需要的程序、插件或其他条件，以该技能自己的说明为准。

## Check extensions without sending a message

**Skills、Commands、Subagents** 页面使用 Scribe 实际注册的条目。技能页在窗口重新聚焦和每次修改后自动重新读取当前库文件，命令页核对其状态，子代理页的 **刷新** 重新读取定义；这些操作都不发送模型消息，也不执行任务。

命令与 **我的指令** 共用同一份 Scribe 命令文件；新建、编辑、启停和删除会影响共享列表及相应快捷入口。删除会把命令文件移至当前资料库的 `.scribe/trash/commands`，而不只是从当前页面移除。更完整的自定义指令选项位于 **我的指令**。子代理页可管理多个自定义子代理，分别设置名称、用途和指令，并可启停或删除。主代理会发现已启用的定义并按需委派；未指定自定义子代理时，仍可通用委派。子代理使用当前聊天的模型与操作权限。定义保存于 `.scribe/subagents`，刷新或重新打开会读取外部修改；编辑、停用或删除影响后续委派，已有任务与记录保留。

本版本不加载旧外部代理的插件市场、插件包、启动钩子或 MCP 配置，也不提供这些安装和导入入口。机器上原有的外部配置文件保留。

## Excalidraw drawings

启用支持的 Obsidian Excalidraw 插件后，Scribe 会注册原有绘图读取、图片预览和写入工具。模型可以按任务选择这些工具。

绘图仍由 Excalidraw 插件创建和保存；写入服从所选权限模式，聊天保留专用卡、打开绘图入口和实际文件差异。插件未启用或某项功能不受支持时，Scribe 显示对应原因。

## Applying a settings change

已有聊天会按其当前任务状态应用配置更改，等待中的变更会显示状态。需要重新加载时，可以使用 **重新加载**；Scribe 会尝试恢复已保存的聊天和当前草稿。重新加载失败时不能保证草稿保留，请先另存需要的未发送内容。
