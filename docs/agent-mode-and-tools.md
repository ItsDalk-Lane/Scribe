# Agent Chat

Agent Chat 是 Scribe 的桌面聊天工作区。Scribe 直接在 Obsidian 内运行自己的代理，沿用你已配置的模型、密钥和连接地址。开始聊天不需要安装或登录外部代理程序。

Quick Ask、Quick Command 继续用于编辑器旁的简短提问和改写，也保留移动端入口。

## Set up Scribe

1. 打开 **Settings → Scribe → 模型**，添加供应商或本机模型，并填写它需要的连接信息。
2. 配置完成且连接可用的模型可直接用于聊天，无需另外启用。可在聊天输入框旁选择模型、推理强度和权限模式。
3. 点击 Agent Chat 图标，或运行 **打开 Scribe 代理聊天窗口**，输入任务。

新聊天记住上次成功选择的模型、推理强度和权限模式。首次使用默认选择配置顺序中的第一个可运行模型，权限模式默认为自动模式；恢复旧聊天时保留该聊天自己的选择。没有可用模型时，请在“模型”页检查服务商连接和凭证；不同设备的密钥不会自动共享。

## Models, effort, and permissions

输入框旁的模型选择用于当前聊天，并记住为之后新聊天的选择。推理强度按模型支持的选项显示；更改后在下一次请求中使用。具体支持情况和费用由你的模型服务决定。

| 模式        | 行为                                                                                 |
| ----------- | ------------------------------------------------------------------------------------ |
| **Default** | 可以读取和搜索笔记；写入笔记、修改绘图和执行系统命令通常需要批准。                   |
| **Plan**    | 保持计划模式时阻止编辑和系统命令；可以审阅、拒绝计划或附反馈退回修改。               |
| **Auto**    | 通常自动允许资料库内普通笔记及绘图编辑；资料库配置目录中的编辑和系统命令不自动放行。 |

权限卡显示具体操作、发起者、命令或文件信息。编辑和命令可选择在当前聊天中始终允许或始终拒绝相同操作；已保存的决定会先于 Auto 的自动放行规则生效，因此系统命令不一定每次都弹卡。其他请求以卡片实际提供的选项为准。**Stop** 取消当前回复及其尚未回答的请求。

批准计划后，当前聊天会切回 **Default**。你也可以手动切换模式，后续操作按所选模式和已保存的授权执行。手动在聊天中切换权限模式，还会更新之后打开聊天时使用的默认模式；批准计划后的自动切换不会更改这个默认值。

提问卡支持多题导航、选项和自行填写。提交后，答案回到提出这组问题的工具；取消会结束这次等待。

笔记工具在写入前检查目标仍是资料库内的普通文本文件，并拒绝多个入口共用的同一份文件。编辑器有未保存内容、文件在读取或批准后发生变化，或助手尚未实际收到完整原文时，Scribe 会停止相应覆盖。经批准的系统命令使用你的电脑权限，可能访问资料库以外的文件或服务；文件工具也无法替其他应用或进程锁住文件。

Note writes check that the target is still a regular text file in the current vault, and refuse files shared by multiple hard links. Scribe stops a replacement when there are unsaved editor changes, when the file changed after reading or approval, or when the assistant has yet to receive the complete source. Approved commands run with your computer's permissions. Scribe cannot lock a file against unrelated apps or processes.

## Context and history

打开的聊天分别保留自己的草稿、待发送附件和排队消息；切换聊天不会把另一条聊天的问题或草稿带进来。尚未点击发送的草稿和附件只保存在运行中的内存里，退出后不能依靠历史记录找回。已被接收的消息会先保存，包括排队等待的消息；重新打开历史不会自动把它们重新发送。请先另存需要保留的未发送文字，并保留附件原件。

- 通过原输入区添加笔记、编辑器选区、网页、图片和其他支持的附件；输入 `@` 或 `[[` 选择笔记。
- 项目保留自己的说明、上下文和聊天列表。当前资料库的个人技能可在不同项目中复用。
- **最近聊天** 和 **聊天历史** 保留查找、重命名、分叉、置顶、复制链接、书签和删除入口。聊天仍保存在当前资料库的 `.scribe` 内，每次只追加新发生的内容；复制链接、加入书签和置顶都不会创建笔记。确认删除聊天会删除该聊天的新记录和显示缓存，保留原有聊天笔记、共享图片和普通笔记。
- 消息下面可以复制正文、在编辑器光标处插入或替换，以及从该处建立新的聊天分支。
- 本次聊天格式改造前创建的聊天不再读取、显示或迁移，包括原先保存在 `.scribe` 内的聊天；旧文件原样保留，不会自动修改或删除。新建聊天从新格式开始。
- 重新打开新格式聊天时，Scribe 从保存的记录恢复内容；显示缓存可以重建。过往工具活动只回放显示，不会重新执行命令或改写文件。中断的任务不会自动重启。
- 图片按实际内容共享保存，相同图片在多条聊天中只占一份。删除一条聊天不会自动清理共享图片；图片缺失时会显示提示，原消息仍保留。

接收用户消息、工具获准即将执行，以及工具返回结果时，Scribe 会等待硬盘确认保存，再继续相应操作。保存失败时会停止新请求和尚未开始的操作。突然断电后，最近一次确认之后、尚未确认写入的内容仍可能丢失；这不是对所有正在显示的文字作出断电保留保证。

恢复时补充的信息会标注为“系统恢复说明”。“未启动”表示没有执行记录；“结果未知”表示操作已获准，但未保存结果，文件可能已经改变。请先核查对应文件和任务，再决定是否重试，不能把“没有结果”当作“没有改动”。

记录部分损坏时，仍会尽量显示可以读取的内容；如果无法确定后续内容的安全顺序，聊天只能查看，不能继续执行任务。保留原件及备份，可另开新聊天继续。

回复支持 Markdown、代码块和供应商实际返回的可展示思考。桌面连接会实时显示已收到的内容；服务商只在结束时返回的思考不会被伪装成逐字输出。思考中，标题显示“正在思考”和单行最新内容，点击展开可查看保留换行的完整实时内容；用时紧跟标题显示。收到模型明确的思考结束信号，或开始输出正文、生成工具调用时，就停止这段思考的计时和动效，不把后续等待算进去；只有内容暂时没有增加时，仍等待模型确认结束。结束后显示实际记录的思考用时。工具执行中，标题按正在做的任务显示“正在搜索文件”“正在查看网页信息”“正在调用子代理”等动态文字；等待批准、成功、失败和取消分别显示对应状态，结束后停止动效。整体计时从 0.1 秒开始，每十分之一秒更新，结束后固定。

正文、思考、工具和计划保持实际发生的顺序。正常结束且本轮相关工作全部结束后，最终答复之前的过程默认折叠到一个大消息块中，标题显示整体用时、思考总用时和实际执行的工具次数。中间工具失败后，只要整轮已经正常收尾，也会折叠过程；标题保留失败和取消数量，展开可查看完整异常记录。展开后仍按原顺序查看，中途的说明不会被挪到最终答复中。并行子代理的思考时间会累加，因此思考总和可能超过整体用时。仍在执行的子任务、失败、停止、额度限制和恢复提示保持各自真实状态；纯正文回复不会产生空过程块。

长聊天先显示最近 30 轮，点击 **再加载前 30 轮** 查看更早内容，完整记录仍然保存。向上滚动时不会强制跳回最新位置；使用向下按钮可继续跟随。

每轮回复的时间戳右侧显示 token 总量和每秒生成速度，点击可在上方查看合计总量、输入、缓存输入、首 token 耗时、步数，以及使用的模型和供应商。输入框右上显示整个聊天的 token 数和缓存命中率，悬停可查看合计用量、轮数、步数及当前上下文容量。两处详情都合计主助手和子代理的用量，不再逐个列出代理明细或额外说明段落。输入 token 已包含缓存部分，总量不会重复相加缓存；缓存命中率按累计缓存读取量除以完整输入量计算。

统计包含主助手和子代理。一步表示实际发出的一次模型请求，包括重试和上下文整理，不包含鉴权或工具请求；一轮为实际送出的用户输入和助手回复配对，进行中的轮次单独标记，未发送的排队消息不计。速度使用服务商报告的输出量，包含思考生成，排除工具等待；多次调用按总输出量除以对应生成用时计算。首 token 耗时从首个实际模型请求发出算到首次收到非空思考或正文，包含重试等待，不包含解锁等待。

统计随原聊天记录保存，重新打开时按原来的轮次与来源恢复。服务商未报告的字段和旧聊天未保存的耗时显示“暂无数据”或“部分统计”，不会估算速度、补造零值或把历史累计量平均分给每轮。

上下文环显示模型实际返回的用量；没有数据时保持缺数状态。这里不再显示外部代理账户的订阅额度。

### Fork a conversation

在一条已完成的回复下选择 **分叉对话**，可从该位置建立独立的新聊天。原来的聊天和任务保留。保存的工具活动作为历史显示，分叉不会复制执行它们。

### Compact a long chat

在主聊天或子会话输入 **/compact**，可让当前模型总结已有聊天。命令后可写本次要保留的重点，例如 `/compact 请保留笔记路径、用户约束和未完成任务`。这只影响当前会话的摘要，不会执行历史中的指令或增加权限。

模型窗口已知时，Scribe 在每次请求前检查上下文，包括同一条消息执行很多步骤的过程中；接近窗口的 80% 或需要为输出预留空间时，会先合并重复的笔记读取内容，仍然过长再压缩较早历史。自动压缩始终保留当前要求和最近完整工具交互的原文。只省略当前上下文中仍有相同全文副本的重复读取；独有内容、旧版本和错误不会因此丢失。

摘要按完整消息和工具交互分块，过大片段才拆开；每块有独立长度限制，必要时最多进行两轮归并，为后续工作留出空间。聊天会显示压缩进行、完成、失败、取消或无需压缩的状态，并可展开查看摘要。完成后占用表立即更新；生成摘要的消费单独计入累计用量，不能当作压缩后的占用。

压缩只改变模型请求采用的上下文：聊天里的完整原文始终保留，可继续向前查看。再次压缩合并已有摘要、之前保留但尚未整理的要求和新增对话；本轮仍需原样保留的要求继续保留。重开按已保存的摘要恢复，保存完成后发生中断也不会把已成功的压缩误报为取消。

摘要被截断、拒绝、返回空内容或无法安全容纳时停止本轮，保留原记录和上次有效摘要。窗口未知时无法提前按比例压缩。模型服务明确报告上下文超限、且尚未输出内容时，会尝试压缩后重试失败的模型步骤一次；不会重新执行已经完成的工具。再次失败、没有可压缩历史或请求次数用尽时停止并提示。

Quick Ask 和 Quick Command 也会检查系统要求、全部对话和本次输入的合计长度，并为输出预留空间。超过已知容量时，会在发送前提示缩短输入、降低输出上限、开启新的快捷对话或换用容量更大的模型；原有对话和未发送草稿保留，不会悄悄删除旧要求。回复因输出上限被截断时，已收到的内容仍保留，并提示它尚未完整结束。

### When a reply stops early

每轮步数默认无限制。可在 **Agent 配置 → 常规** 中明确选择限制并填写正整数；已经保存的上限继续生效。达到上限时，已执行的工具结果会交给模型，再进行一次不允许调用工具的收尾，总结完成事项、剩余工作及继续方式。若收尾仍要求工具调用，该调用不会执行。子代理也会收尾，并把达到上限的原因和实际总结交回父聊天。

如果工具参数因输出长度限制而不完整，该工具不会执行，补救请求也计入步数。达到上限时直接停止，不再追加请求反复补写参数；已有结果和未完成原因仍保留。

步数上限、服务额度不足、身份验证失败、上下文问题、请求失败和主动取消分别显示原因。额度不足会立即停止，不再自动重试；这是服务账户限制，不是代码错误，补充额度或重新打开会话后可发送新消息继续。只有明确的临时故障才有限重试；已经显示部分回答或工具调用后，不自动重放整个请求。

错误分类依据服务商返回的结构化信息。若兼容服务只返回一段文字，或只给出无法区分额度和限流的状态，Scribe 会显示普通请求失败并停止自动重试，不猜测原因。自动停止后，尚未读取的排队内容会保留供你再次发送；已完成的操作不会回滚。

## While the agent works

### Send a message

可以在代理工作时继续输入。发送的排队消息会先保存，再等待代理下一步读取；**撤回排队消息** 将尚未读取的内容及附件放回输入框。**立即发送** 会停止当前回复，再立即处理等待消息。

### Background subagents and commands

Scribe 可以委派真实子代理，也能执行前台或后台系统命令。每个任务有自己的身份、输出和状态。子代理在独立上下文中工作，将结果交回父聊天，并使用对应的权限请求。

打开输入区上方的任务入口，可以查看子代理详情、后台命令的真实输出尾部、截断提示及成功、失败或停止状态。关闭详情仅关闭视图。**停止任务** 停止指定任务；其他任务继续运行。主回复结束后，后台任务仍可单独保持运行。

**子代理** 入口列出当前聊天中的每个子代理，按**正在执行**和**已完成**分组；每一项代表一个独立的子代理实例，同一子代理的多次执行仍是一项。点击列表项会打开该子代理的聊天界面：顶栏左侧是返回按钮和子代理名称（模型委派时可以为它起名，未命名时沿用任务描述），右侧是它使用的执行模型；下方是与主聊天相同的消息区和输入框，但没有输入框上方的工具栏、模型与模式选择器，也没有多聊天标签页。主对话发给子代理的消息在这里显示为用户消息；子代理执行期间收到的消息，按发送时机显示与主聊天一致的排队样式。子代理向主对话回报进度或提问时，消息流中会出现「正在回复主代理」「正在询问主代理」等提示。在这里输入补充命令的规则与主聊天相同：子代理执行中不会被打断，消息按顺序等待下一步处理；空闲时发送会直接开始新一轮执行。停止、归档、删除和恢复确认在该界面的更多操作菜单中完成。子代理聊天界面的打开位置（左侧边栏、右侧边栏或悬浮面板）可在 **Agent 配置** 中设置。停止不能撤销已经完成的编辑或远程操作。

子代理的发现、提问、阻塞和结果会标明来源，既能在主聊天中查看，也会交给主模型处理；这些状态不表示模型已经理解。普通进度不会逐条启动主模型；迟到结果仅保留查看，不重启已经停止的任务。

可以直接在子代理聊天输入框发送纯文字来追加任务，不需要先添加附件；排队和重试会保留这条用户输入。子代理聊天支持添加笔记、网页、图片和选中的内容，与主聊天一样可通过输入框添加参考内容。图片需要子代理使用的模型支持识图；发送失败时输入和参考内容会保留，供检查后重试。

如果消息已保存但子代理暂时无法启动，消息会留在等待区。排除原因后，点击**重试等待中的消息**即可继续，无需重复输入；如果仍无法启动，消息会继续保留。

新建子会话的上下文随原聊天保留。重新打开聊天、回收空闲聊天或重启 Obsidian 后，可以继续同一个子会话；不会因为列表只展示最近任务而丢失。恢复只加载记录，未确认结束的工具显示中断或结果未知，不会自动重做。缺少完整上下文的旧任务只能查看；模型失效或原工作位置不再可用时，需要先处理提示的原因。若旧后台命令的实际状态无法确认，先检查文件和进程，再明确确认已核对；确认本身不启动模型，也不重新执行命令。

笔记编辑会检查同一文件的并发修改，冲突时需要重新读取；系统命令直接修改文件不受这把笔记写入锁保护，不能保证多个子代理互不影响。

子代理默认使用主聊天当前允许的工具和技能；角色限制只能缩小范围。一次批准只放行对应操作，不能替其他子代理授权；技能内容也不能提供额外权限。归档保留上下文并停止自动安排，取消归档后可继续。删除会清除该子会话的恢复资料，主聊天已经引用的结果仍然保留。

手动选择的技能只授权给当次子代理执行。若技能停用导致执行失败，重新启用后，可在主聊天用 `/技能名` 明确选择该技能，并要求主代理让原来的空闲子代理继续；新授权只用于这次继续执行。子代理还在运行或有未处理的指令时，先等它完成，再重新授权。

每个接收方最多等待 100 条消息，每条最多 20,000 个字符；超出会明确拒收，不自动删减。完成结果始终先保存，收件箱满时显示交付受阻，腾位后再送入主模型。

可在 **Agent 配置** 调整同时执行数量、排队数量与整项任务的模型调用次数。默认同一资料库各聊天合计同时执行 3 个子代理、最多等待 20 个；每项主任务与其子代理合计最多调用模型 100 次，包含重试和上下文整理。达到上限保留进度并停止新请求，这不是精确的费用上限。主对话中达到上限的任务会显示加额入口，可为对应原任务明确增加一次额度；保存成功后显示回执，不会自动重跑。

## MCP 服务器

在 **Settings → Scribe → MCP** 配置 MCP 服务器。支持三种连接方式：本地命令（stdio，例如 `npx`、`uvx` 启动的服务器）、SSE 远程服务器和可流式传输的 HTTP 服务器；配置项与常见 MCP 客户端的 JSON 格式互通，可从 JSON 导入，也可一键复制导出。

每个服务器行内即可启用或停用；点击行进入详情，可修改名称、类型、描述、命令/URL、参数、环境变量、请求头、超时和长时间运行模式，并逐个工具决定「启用」与「自动批准」。自动批准的工具调用时不再逐一请求确认；未自动批准的 MCP 工具与内置工具一样走人工确认。已保存的敏感凭据（如 Authorization 请求头、API Key 环境变量）以加密形式存放在当前库 `.scribe/secrets`，配置文件中只留引用、不回填显示；删除服务器会连同其保存的凭据一起删除。

JSON 导入也会先加密认证信息，再保存服务器；失败时保留输入，修正后可重试。同名服务器会跳过并提示，不覆盖已有配置。导出不会包含已保存的认证信息，需要在目标客户端另行填写。 替换认证信息时先保留原凭据，服务器配置保存成功后才清理旧凭据。保存失败仍可使用原配置；清理失败会单独提示，已保存的配置仍然生效。

服务器启用后自动连接：行内圆点显示连接中、已连接（含服务器版本号）、错误（悬停查看原因）或已停用；连接成功后，其工具自动进入下一轮对话，无需重启聊天。停用、删除或修改连接配置后，改动在下一轮请求生效。

## Review what a turn changed

工具活动保留读取、搜索、编辑、命令、网页和技能卡片。MCP 调用展开后分为“输入”和“输出”，保留完整参数、结构化结果和每个返回内容块。JSON 文本只调整缩进，保留原来的字段顺序、数字和字符串，Markdown 按标题、列表、表格、代码显示，普通文字保留换行，图片、音频和资源按返回类型呈现。长结果可逐段加载、滚动和复制完整原文，不会总结、改写或截掉末尾。文件修改继续使用专用差异展示。结构化结果保留连接组件交付的数据；如果服务端直接把超大整数作为 JSON 数字发送，连接组件可能已在交付前损失精度，界面不会猜测或修补该数值。需要绝对精确的长编号时，服务端应以字符串或原始文本返回。

写入或编辑后，变更摘要显示实际文件数和修改前后的差异。拒绝执行的操作不会被列成已写入。绘图在已发生部分修改后失败时，也保留实际变更。

## Skills

在 **Settings → Scribe → 技能** 管理当前资料库中的全部技能。点击“添加技能”，可选择 **Agent 创建、系统搜索、本地导入**：

- **Agent 创建**：用日常语言描述方法或流程。打开的聊天会自动带上内置 skill-creator 技能的调用（与技能列表“立即使用”一致）；如果该技能已停用，会先询问是否启用，已卸载时会提示先恢复内置技能。Agent 提供完整草稿，你可修改名称、说明、作者、版本、标签和正文；只有你点击“保存”后才安装。保存开始前取消或关闭确认窗口不会安装技能；保存期间关闭会尝试取消尚未提交的写入，已经完成提交时会按实际结果报告保存成功。
- **系统搜索**：按需查找电脑上支持的其他工具技能位置，显示名称、说明、来源与冲突状态。可逐项或批量导入，原来的技能文件始终保持不变。
- **本地导入**：在弹窗中直接拖放技能文件夹、ZIP 压缩包或单个技能 Markdown 文件，也可以点击拖放区或下方按钮打开文件选择；检查预览后导入，可识别压缩包或文件夹内的单层技能目录。单个 `.md` 文件需以合规的元数据块开头，文件名推导技能名（遵循同一命名规范与冲突规则），入库时展开为标准技能目录。每个技能最多 2000 个文件、50 MB。不安全的路径、文件链接、无效格式和跨来源同名会被拒绝。

导入的技能若存在轻微格式问题（如描述值含冒号未加引号、开关字段写成 yes/no 等），导入流程会自动尝试受限修复，并在确认窗口逐行展示“修改了什么”；只有你确认后才安装修复后的副本，原始来源文件永不修改。无法自动修复的技能维持拒收，可从详情页发起 Agent 修复。

所有技能和附带资源都保存在当前库 `.scribe/skills`。导入得到独立副本，原始来源后续变化不会自动同步；从相同来源重新导入需确认替换，副本中的修改也会被覆盖。名称会统一为小写英文、数字和连字符，最长 64 个字符，导入前可查看最终名称。已有无来源标识的技能显示为“本地”，继续可用；直接放入合规文件夹后，刷新或重新打开设置即可读取。不会扫描项目工作文件夹或创建技能链接，也不会自动读取、搬移或清理旧位置资料。

每行右侧依次是“立即使用”、启用开关、“卸载”按钮。点击名称或说明在设置页内进入详情页，返回按钮回到列表。详情顶部显示名称、版本、来源和全局启用状态；左侧“源文件”列出描述文件及支持文件，右侧查看所选文件。非内置技能可切换“预览/编辑”，直接编辑完整文件，包括描述文件中的全部元数据和正文；编辑会自动保存，切换文件或返回前等待保存完成，冲突时保留草稿并可重试或重新载入。切换到 Obsidian 的其他设置后再打开同一技能，可继续未保存的修改；重启插件前请等到“已保存”。Agent 创建确认仍须明确点击保存。内置技能只读。改名同时更新技能文件夹，保存时检查重名和外部修改。立即使用只打开引用技能的聊天草稿，不自动执行任务；已停用的技能会先询问是否启用。关闭开关会保留文件，卸载则删除库内技能及全部附带文件。格式有误的个人技能可从详情页让 Agent 修复。

Scribe 随插件附带 **skill-creator、defuddle、json-canvas、knap、obsidian-bases、obsidian-cli、obsidian-markdown** 七项技能，首次安装默认启用。内置技能在应用中只读，可停用、卸载，也可通过“恢复内置技能”找回；明确卸载的项目不会在重启或升级后自动恢复。升级遇到已有同名个人技能时跳过，不覆盖；内置文件在应用外修改过时保留现有内容，用户可选择保持原样或确认重置。内置技能的许可证、固定版本和来源说明随技能一起保存。

安装技能不会安装外部程序或执行附带脚本。Defuddle、Knap、Obsidian CLI 等能力需要按技能说明准备对应工具。skill-creator 的基础撰写使用 Scribe 会话；Claude 专用评估脚本不会从 Scribe 自动运行。只有明确要求评估时才生成工作资料，并保存在当前库技能目录的内部工作区中。
技能导入和编辑只修改指定内容，未修改的元数据保留原文，包括高精度数字和原有字段形式。已在独立 macOS 测试库核对真实导入、保存、重载和取消；这些结果不代表 Windows 或实体移动设备已经实机验证。

Skill imports and edits preserve untouched metadata text, including high-precision numbers and existing field representations. Import, save, reload, and cancellation were verified in an isolated macOS vault; Windows and physical mobile devices were not verified.

在聊天中输入 `/` 打开斜杠菜单。菜单按 **命令、技能、子代理** 三组显示，每组有组标题；每个条目名称后带「内置」或「自定义」标签：`/compact` 与内置来源的技能标「内置」，自定义 Agent 命令、其他来源的技能和子代理标「自定义」。输入文字会在各组内分别模糊匹配，组顺序保持不变，没有匹配条目的分组自动隐藏。

选中技能或 `/compact` 后，命令在输入框中显示为一个带类型图标和高亮背景的命令标签（只显示命令名）；实际发送的文本仍是 `/命令名`，模型看到的内容不变。通过“立即使用”或 Agent 创建等方式带入的命令草稿同样显示为该标签。模型也可以调用已注册且允许自动调用的技能。[Scribe 命令](custom-commands.md)从编辑器或 Obsidian 命令面板运行，不在当前代理聊天中展开。手动选择的技能在当前任务中可读取其附带文件；重新打开聊天或开始新的独立任务后，需要重新选择才能读取仅手动技能的附带文件。较长的技能内容或列表可分段读取；如果内容在读取期间改变，需从头读取。

选中子代理后同样留下命令标签，在其后补充任务描述再发送：这条消息不会交给主模型，而是直接委派给对应子代理在后台执行，结果由现有的后台子代理机制自动回传主聊天。子代理命令词取其名称（名称含空格时使用标识），只有消息以该命令词开头且带有任务描述时才会触发委派；只输入命令词、或没有匹配的已启用子代理时，按普通消息发送。委派消息不携带图片，也不作为回合中途的插话，而是排队到下一回合执行。命令识别优先级为 `/compact`、子代理、技能。子代理分组仅在代理模式已激活后端时出现。

模型看到的技能清单随每轮请求重建并声明“旧清单作废”，清单受上下文预算约束：默认不超过当前模型上下文窗口的 2%，且绝对不超过 10000 token，两项均可在 Agent 配置中调整。超出预算时先移除占用空间最大的条目，极端情况下只保留技能名；设置页会显示当前预算状态和未进入模型可见列表的技能名。被移出清单的技能仍可被模型通过无参数调用技能工具列举获知。技能正文与支持文件的读取共用统一的大小上限，超限内容会被截断并明确标注。

手动选择的技能在模型开始回应后，会保留当时实际提供的正文，供同一聊天继续、整理上下文和重开时使用。模型自行读取的正文，只有在后续请求实际带上内容并收到回应后才会保留；长正文仅保留已交付的部分。停用技能、更改正文或位置后不会恢复旧正文；依赖状态改变时需重新选择或读取技能。如果旧摘要可能含已失效的技能内容，系统会停止发送并提示新建聊天。保留正文不会把重开前的附件读取或转交子代理资格变成新的授权；空间不足时会提示。要将新工作与此前的技能上下文隔离，请新建聊天。

技能需要的程序、插件或其他条件，以该技能自己的说明为准。技能也可以在元数据中声明依赖清单（命令行工具、Obsidian 社区插件或 Python 包）：详情页会逐项显示本机检测结果（已就绪时给出实际路径或版本），未就绪项附安装指引；安装动作始终由你手动完成，安装技能本身不安装任何外部程序，投递给模型的技能正文也会附带当前环境的依赖状态。技能还可携带可选界面元数据（显示名、短描述、图标、品牌色、默认提示语）：列表与详情优先显示它们，「立即使用」以默认提示语作为聊天草稿；编辑这些字段不会改动其余元数据原文。

每次技能投递（模型自动调用或你手动调用）都会记入纯本地使用台账，保存在当前库 `.scribe` 内并区分调用来源，不外传任何数据。技能列表按管理器返回的固定顺序显示，行内显示使用次数与最近时间；超过 90 天未使用的技能会收到温和的清理提示。删除技能时台账记录一并清除，重新安装后计数从零开始。系统搜索遇到无法读取的来源时会明确标记“本次扫描不完整”，列出失败原因并在重新扫描时自动覆盖失败分支；未标记不完整的列表才是完整候选。

## Check extensions without sending a message

**Skills、Commands、Subagents** 页面使用 Scribe 实际注册的条目。技能页在窗口重新聚焦和每次修改后自动重新读取当前库文件，命令页核对其状态，子代理页的 **刷新** 重新读取定义；这些操作都不发送模型消息，也不执行任务。

**命令** 页管理 Agent 的斜杠命令（内置 `/compact` 与自定义 Agent 命令），保存在当前资料库的 `.scribe/agent-commands`；**我的指令** 管理编辑器和命令面板使用的快捷指令，保存在 `.scribe/scribe-custom-prompts`。两者互不影响：在 **我的指令** 中删除会把指令文件移至当前资料库的 `.scribe/trash/commands`，而在 **命令** 页删除会直接删除对应命令文件，不进入回收站。子代理页可管理多个自定义子代理，分别设置名称、用途和指令，并可启停或删除。已启用的子代理同时出现在聊天斜杠菜单的「子代理」分组中，可从输入框直接委派。主代理会发现已启用的定义并按需委派；未指定自定义子代理时，仍可通用委派。子代理使用当前聊天的模型与操作权限。定义保存于 `.scribe/subagents`，刷新或重新打开会读取外部修改；编辑、停用或删除影响后续委派，已有任务与记录保留。

本版本不加载旧外部代理的插件市场、插件包、启动钩子或 MCP 配置，也不提供这些安装和导入入口。机器上原有的外部配置文件保留。

## Excalidraw drawings

启用支持的 Obsidian Excalidraw 插件后，Scribe 会注册原有绘图读取、图片预览和写入工具。模型可以按任务选择这些工具。

绘图仍由 Excalidraw 插件创建和保存；写入服从所选权限模式，聊天保留专用卡、打开绘图入口和实际文件差异。插件未启用或某项功能不受支持时，Scribe 显示对应原因。

## Applying a settings change

已有聊天会按其当前任务状态应用配置更改，等待中的变更会显示状态。需要重新加载时，可以使用 **重新加载**；Scribe 会尝试恢复已保存的聊天和当前草稿。重新加载失败时不能保证草稿保留，请先另存需要的未发送内容。

### 规则和资料的更新

每次模型生成前，Scribe 都会重新组装当前规则、模式、项目资料声明和可用工具。同一任务里修改说明或更换资料后，从下一步开始生效；已发出的请求和你原先发送的选区、附件不变。压缩或重开聊天后仍使用当前声明。聊天更多菜单中的“查看上次请求”读取保存的实际输入，方便核对过去那次回答采用了哪些内容，不会自动重发请求。

### 网页搜索与搜索技能

聊天里的网页搜索按 [Agent 配置](settings.md#网页搜索) 中的首选来源执行。Scribe 直接控制调用顺序。MCP 派发前会拦截网页搜索工具和用途未经确认的工具；普通 MCP 工具需由用户确认可直接调用。明确失败后才继续尝试已配置的备选，取消、拒绝或无法确认结果时停止。读取已知网址仍使用独立的网页读取工具。

技能作者可在 `SKILL.md` 顶部的配置区声明 `web-search-command: scripts/search.py`。路径指向该技能目录内的 Python 脚本。Scribe 把完整搜索词作为一个参数交给脚本（Python 中的 `sys.argv[1]`），并读取 UTF-8 输出。退出码为 0 且有输出表示成功，例如可输出 `{"results":[]}` 表示搜索成功但无匹配。非零退出码或空白输出表示失败。执行遵循命令权限，超时或中止后不会自动切换。脚本拥有本机进程的权限，请只安装信任的来源。

### 工具执行、文件保护与长结果

普通独立读取可以同时进行，但数量有限；文件修改和需要你回答或批准的操作按顺序处理。不同子任务仍使用独立的提问、批准和结果，不会把一个子任务的允许用于另一个。工具停用、项目位置或权限改变后，尚未开始的调用会在执行前再次检查。

整篇替换已有笔记前，助手必须在此前的模型步骤实际收到完整当前版本。同一次回复同时发出读取和覆盖，或读取结果被裁去一部分，都不能据此覆盖；你随后修改笔记时也需要重新读取。局部替换只改指定的原文。未保存的编辑内容也会阻止整篇覆盖。绘图修改使用最近实际读到的场景版本；多个修改步骤中途出错时，会如实说明已经保存的部分。

长结果可能分段提供给模型，完整原件仍随聊天或原有命令任务保存。结果会说明是否完整，并提供继续读取的入口；继续读取不会重新执行原来的写入、命令或远程操作。目录、搜索和网页也可继续读取，来源改变后旧游标失效。旧输出占满预算时优先保留刚读的新页。已保存的技能正文仅供历史查看，助手要继续使用技能须重新读取当前启用版本。命令结果始终显示状态、退出码、任务编号和完整输出位置。远程调用超时只表示无法确定结果，助手必须先核实，不能直接重复可能已经完成的操作。

这些保护覆盖 Scribe 自己管理的文件工具。任意命令、其他应用和其他进程仍可能修改同一文件，不能把项目工作位置理解为系统隔离环境。

### 回答生成与排版

聊天会持续显示已收到的完整文字，同时合并来不及处理的中间排版版本。普通聊天、子聊天和任务详情中的相对链接从资料库根目录查找；快速问答仍使用提问时的笔记位置，切换当前笔记不会改变已有回答的链接来源。

代码与图表生成中先显示完整源码，内容闭合后再安排高亮或绘图；未完成的公式保留原文。单个代码或公式块超过 50,000 字符时跳过自动增强，排版失败时同样保留可读、可复制的原文。回答完成后保留正文和选区，过程内容继续按原规则折叠。向上阅读时，新内容或排版变化不会强行把你拉回底部；点击返回底部或发送新消息可以恢复跟随。
