# 数据保存合同

本文件约束 Scribe 的所有新功能与后续修改。旧代码中的历史路径不是新功能设计依据。修改持久化前必须阅读本文件和顶层 AGENTS.md；目录本身不能配置到其他位置。

## 两个保存位置

1. 插件 `data.json`：用户明确配置、轻量偏好、存储元数据、恢复所需稳定标识以及密钥引用。通过现有设置保存流程写入，不另外复制一份配置。
2. 当前资料库根目录 `.scribe/`：其余所有插件文件资料，包括新增功能的数据。不同资料库各自保存，不使用电脑级共享数据根。

模型网络连接方式由运行平台自动决定，不保存用户可配置的连接通道；旧配置中的 `enableCors` 在现有设置加载和保存流程中丢弃，模型、地址与密钥引用保持不变。

不得新增电脑用户目录、系统临时目录、Obsidian localStorage 或 SecretStorage 的插件数据写入。内存中的临时状态可以使用；若需要跨重启保留，就按上述两个位置分类。

| 模型目录缓存        | `.scribe/model-catalog-cache.json`                                                                                                                                                                                           |
| 供应商配置          | 插件 `data.json` 顶层 `providers`；连接信息、密钥引用和“在模型选择器中包含该供应商模型”开关逐条保存，开关缺失即包含，旧配置无需改写（https://github.com/ItsDalk-Lane/Scribe/issues/69）                                      |
| 供应商检查结果缓存  | `.scribe/provider-verification-cache.json`；按供应商记录最近一次检查结果与配置指纹，指纹不匹配自动失效；打开模型页先显示缓存，不发网络请求（https://github.com/ItsDalk-Lane/Scribe/issues/39）                               |

| 其他新功能          | 在 `.scribe/` 下选择明确用途的目录，并在本表补充实际合同；不得照搬旧目录                                                                                                                                                     |

目录按需创建，不为了表格齐全而预建空目录。`system-prompts/` 是没有设置管理入口的旧功能，已退役，不是当前新功能的保存位置；不得继续创建、读取或据此添加新功能。旧文件不自动删除。

MCP 凭据替换先写入带随机版本标识的新加密引用，原密文保留；移除凭据行或服务器时，先成功保存配置，再清理不再引用的密钥。保存失败不发布新配置、不删除或覆盖原凭据；已写入但尚未引用的加密暂存仍留在同一密钥仓，不另换位置。重开只按已保存的引用解析。清理失败单独提示，不把已保存或已删除的服务器说成操作失败。

## 用户工作文件例外

- 库级说明：库根 `AGENTS.md`。
- 项目说明：该项目实际工作文件夹中的 `AGENTS.md`。
- 普通笔记和用户交付物：遵循用户明确选择的位置，不强制搬入 `.scribe`。

项目配置文件夹不是工作文件夹。创建项目时，用户可明确选择已有库内文件夹；未选择才在库根创建同名文件夹。同名文件夹已存在必须要求明确选择。工作位置要校验真实目标，不得指向库外或插件／Obsidian 数据目录。改名不搬文件，删除项目只删除项目配置。

## 隐藏文件读写与失败保护

- 不依赖 `getFiles()`、普通笔记列表或 metadataCache 发现 `.scribe` 文件。复用 adapter 和现有专用存储组件。
- 普通资料写入复用 `vaultFileStore`；聊天追加记录和附件使用各自已有的存储合同，不重写一套保存框架。
- 暂存文件必须与目标一起留在 `.scribe`。保存失败保留原文件和可重试输入，显示错误，不改存其他位置。
- 编辑要保护打开后的外部修改，避免用旧列表内容覆盖新文件；成功后更新列表，刷新和重新打开重新读取磁盘。
- 不扫描或迁移旧根目录，不导入旧聊天或钥匙串。一次性手工清理必须有用户明确授权，不能变成自动启动逻辑。

## 子会话协作与恢复

子会话运行资料随原主聊天保存，不另建聊天文件，也不与 `.scribe/subagents/` 的可复用角色定义混存。`NativeSessionStorage` 读取同一日志，`subagentState` 按格式版本、递增修订与稳定消息编号恢复子目录及独立原生上下文。任务卡片裁剪和空闲运行时回收不删除这些资料；只有新格式的完整子会话可继续，旧任务仍仅供查看。

消息接收、原生上下文与交付状态、执行结果和待交付状态分别在同一次可靠提交中保持一致。只有保存成功才确认接收或宣布结束；重试使用同一消息编号去重，未知或损坏格式保留原件并停止相关写入。重启不沿用自动接续许可，不重放未知结果的工具、命令或远程动作，也不恢复旧的单次批准。

子代理收到消息的日志序号保存在同一子会话记录中，用于将补发消息放回执行过程的实际位置；重开时也可从同一日志中的已提交投递记录恢复。没有可靠序号的历史内容保留原有展示方式，不以时间推测顺序。保存失败仍保留原记录，不改用其他位置。

删除子会话先停止受管执行，再在同一日志写入队列中清除其恢复资料。重写保留原序号和无关记录，不移动已有消息引用；已进入主聊天的结果正文仍随主聊天管理。重写暂存为同目录的 `<聊天>.jsonl.<随机标识>.redact.tmp`，故障恢复备份为 `.redact.backup`：成功后不留备份，替换前失败原件不动，替换后目录同步失败则保留原件备份并冻结写入。不会自动从这些备份恢复，也不改存到其他位置。归档只停止自动调度，仍保留上下文。

并发、等待队列和主任务请求预算只作为轻量数值保存在 `data.json`。凭据继续按请求解析，不进入子上下文、消息、结果或诊断正文。

## 模型请求输入快照

每次实际请求派发准备，在原主聊天 `.scribe/chats/v2/<聊天标识>.jsonl` 追加版本化 `request_context` 事实，不新增目录或把正文保存到 `data.json`。`NativeBackendProcess` 固定请求编号、回合、主／子会话、模型和用途，`NativeSessionStorage` 通过既有可靠写入队列保存。事实保存的是交给模型适配层的输入：当前命名规则区段、项目资料声明、模式、技能注入、工具名称／说明／参数，以及消息的顺序与正文指纹。原日志正文指纹相同才引用原序号，临时或已经改变的内容保存当时正文；指纹不受对象字段顺序或图片恢复新增的内部附件标识影响，预览剔除该内部标识，实际图片数据变化仍拒绝。数组顺序保持原样。不保存连接配置、请求头、凭据或执行函数。

保存失败时停止该次派发，保留原聊天并明确报告，不能将准备记录当作模型已收到请求。普通重试复用同一步内容，压缩补救形成新的输入指纹。关闭重开仍从原日志查看当时输入；“查看上次请求”只读取保存记录及其原消息引用，不读取现在的说明文件，不重新执行工具，也不恢复旧权限。缺失或指纹不符的引用明确报错。供应商适配仍可能转换内容，因此该快照不声称逐字重现网络请求。删除子会话时清除其所属快照，主聊天已经提交的事实继续保留。

## 上下文压缩事实

用户显式调用且模型已经开始回应的技能正文，以带原始正文指纹、依赖状态和调用消息标识的 `skill_delivery` 事实保存在同一聊天日志。模型自行读取的正文仍由原始工具结果承载，仅在实际请求带上结果并收到回应后，以 `skill_model_delivery` 保存原调用与结果的日志序号及所属主会话或子执行；不复制正文。恢复检查来源、资格、版本与连续页，缺失或损坏记录时停止，不推断已送达。子会话删除时清除所属恢复事实；独立任务屏障、技能停用或内容变化阻止旧记录复活。后续请求和重开不因此恢复文件操作、命令或子代理转交权限。旧摘要可能包含失效正文时停止并提示新建聊天。保存失败时停止本次流程并保留原记录，超过恢复预算时明确报错，不把截断内容当成完整恢复。（https://github.com/ItsDalk-Lane/Scribe/issues/68）

压缩继续保存在原主聊天 `.scribe/chats/v2/<聊天标识>.jsonl`，不新增目录或第二份聊天。`NativeBackendProcess` 通过现有保存队列提交派生 `compaction` 事实，内容包括原消息序号、摘要、保留范围，以及同一操作编号的完成元资料（主／子会话归属、模型窗口、压前压后估算）。只确认提交后才启用新摘要和发布完成；失败保留原文与上次有效摘要。生成摘要、归并和超限重试继续使用原模型请求记账入口。

重开由同一记录恢复有效摘要；若摘要事实已保存而完成通知尚未保存，以事实序号补回同一操作的完成状态，按编号更新原卡片，不重复执行模型或工具。旧事实缺少完成元资料时保留原恢复方式。压缩占用和累计消费独立，重新打开主会话时按当前系统要求、模型和有效上下文重算占用。历史工具缩减只作用于内存请求视图，不改写原记录，不省略没有相同完整副本的独有内容。（https://github.com/ItsDalk-Lane/Scribe/issues/66）

## 聊天真实用量与计时

Google 原生协议上下文沿用聊天日志中现有的文本、思考和工具内容字段，保留供应商返回的签名与原始分段，包括仅有签名的空文本段。保存和重开不合并这些段；切换供应商或模型时，仅在请求投影中移除不兼容的内部思考状态并成对转换工具编号，不改写原日志，也不重放工具。（https://github.com/ItsDalk-Lane/Scribe/issues/60）

真实用量事实复用主聊天 `.scribe/chats/v2/<主聊天标识>.jsonl`，不另建统计文件，也不写入 `data.json`。`NativeBackendProcess` 在请求派发时固定独立回合、主／子代理、模型与用途；`NativeSessionStorage` 沿用现有串行日志排队保存，但用量事实不强制落盘，模型回调不直接等待它保存完成；共享队列的排队和写入等待均有时限，保存失败与无响应的处理见下文。每个逻辑调用有稳定标识、实际请求标识列表及请求到尝试的稳定映射，重试与协议续请求只增加实际调用步数；同一 SDK 终态用量按调用来源只计一次，不向各 HTTP 请求分摊。工具只在真实执行准入后记入次数，批准前等待不算执行。

`UsageTracker` 从同一日志投影回合、模型来源与聊天累计，用量保留“未报告”和明确零的区别。输入数包含缓存读写；缓存命中率按缓存读取数／完整输入数计算。速度只合并用量与生成区间都完整的同组调用，输出数已包含思考，不重复相加；首次输出以首个思考或正文原始增量计时。聊天与消息中保存的展示投影可恢复，但不能成为另一份用量权威来源。

子回复的正常完成状态与整体用时按“子会话＋独立回合”恢复：初始执行使用自己的实际开始、结束与结果状态，中途追加的用户回合使用同一日志中带任务归属的回合开始／结束事实。新输入已投递时，前一轮止于该边界，不把整次子执行时长复制或平均分给各轮；父回合成功不证明子回合成功，缺记录或只知中断时刻范围时保持未知。

思考结束边界以原聊天日志中的独立事实保存，绑定原响应段及内容位置，由实时消息和历史恢复共同使用。仅收到明确结束信号或切换到正文、工具调用时关闭该段，重复边界不延长用时；旧记录缺少这一事实时保留原来可证明的数据，不按最后文字时间补造结束时刻。

重开时按调用标识取最后已保存事实去重，保留未完成请求的真实步数并显示缺失／部分统计，不重新发请求或工具。旧记录仅显示已能证明的用量，不把旧聊天累计平均分配给各轮，也不把缺字段补成零。用量事实的保存排队执行但不强制落盘，模型回调不直接等待；写入明确失败时只记日志并丢弃这一条，不冻结整个聊天。写到一半的残留字节在下一次保存前截回原来的完整位置，序号不前进，这一条缺失在重开时显示为部分统计。原生存储和日志存储的排队、写入与落盘确认等待分别从进入对应步骤起计时，每步最多 30 秒；队列中的多条记录同时计时，不逐条累加等待。未开始的过期操作不再执行，已经开始但无响应的写入仍独占真实写队列，直到它完成，避免迟到写入与重试并发。超时只表示结果未知，不把会话永久冻结；磁盘恢复且原写入结束后可重试，工具准入和预算等必要控制记录没有确认成功时不得执行。正文和思考增量先展示，显示不代表保存成功，也不伪造日志序号；显示分段的保存超时后仍可继续展示，可靠正文保存、收尾或停止遇到超时则明确报告未确认保存。只有确认真实的非观察性写入或同步失败才沿用聊天冻结与报错机制，保留原日志和可重试输入，不另换保存位置。回合结束的保存只等写入完成（它同时是收尾事件的持久化屏障），落盘确认在后台补做，失败只记日志。（https://github.com/ItsDalk-Lane/Scribe/issues/52 ，https://github.com/ItsDalk-Lane/Scribe/issues/55）

## 密钥

复用现有 SecretStore，不新增明文字段或第二套加密实现。使用主密码派生的 AES-256-GCM 加密，PBKDF2-HMAC-SHA-256 为 600000 次迭代并使用随机盐；每次加密使用新的随机初始值。

主密码不落盘，停用插件或关闭库后释放解锁状态。查看设置、检查存在性和显示模型只查询元数据；请求准备时只解析对应服务商的凭据。失败、损坏或取消不得继续发请求。表单不回填已存密钥，留空保留、替换和清除均使用明确操作。

设备解锁包（https://github.com/ItsDalk-Lane/Scribe/issues/37，用户批准的对"不落盘"的唯一让步）：设置 `secretsRememberOnDevice`（默认开）且桌面端操作系统加密服务可用时，成功解锁后把主密码经系统加密服务（Electron safeStorage）包裹为 `.scribe/secrets/device-unlock.json`；下次解锁前先尝试恢复并仍要通过既有主密码校验，校验失败即删除该文件并回到人工输入。关闭设置开关、重置密钥存储都会删除该文件；移动端与无系统加密服务时全程不写该文件。该文件离开本机与本应用账户即无法解密，密文文件本身仍不含任何明文。

## 每次新增持久资料的验收

- 在本表写清位置、文件内容归属、对应读写组件和重开恢复方式。
- 验证隐藏目录不被普通笔记列表发现时仍能加载、编辑、刷新和删除。
- 验证保存失败及外部修改保护，不产生其他位置的备用文件。
- 验证重启后恢复，新增插件资料只出现在本合同允许的位置。
- 涉及界面或用户说明时，同步更新相邻预览、帮助及必要测试。

## 技能添加与来源边界

所有来源仍只在当前库 `.scribe/skills` 中保存真实技能副本。无来源记录的现有文件按本地技能处理，不自动迁移或改写。用户打开系统搜索时可以只读扫描明确列出的外部技能目录；导入只读取完整快照，绝不写回、监控或为外部来源创建链接。

来源管理记录不存技能正文，内置卸载意图也不依赖通用设置重置。安装和重导入使用技能库内暂存与备份，失败不转存用户目录或系统临时目录。技能正文、支持文件和来源记录必须作为同一次操作完成；有外部修改时停止覆盖。正常启停仅改描述文件中既有启用字段，不算内置内容的越界修改。技能详情只列库内的安全文件；文字支持文件按打开时原文检查后保存，二进制只读。完整描述文件编辑保留用户提交的原文与配置；重新导入仍保留当前启停选择。

技能撰写聊天的用途保存在现有聊天配置事实中，重开、分支、替换模型仍保留读取与确认保存的工具限制。完整草稿随普通聊天记录保存，不作为已安装技能出现；只有用户确认后，统一技能管理入口才安装标记为Agent创建的副本。恢复历史不会自动保存草稿或重新执行工具。
