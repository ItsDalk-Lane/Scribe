## 共享协议、手动 ID 与既有供应商入口

- OpenAI 默认 Responses，显式 apiShape=completions/responses 优先；兼容供应商默认 Chat Completions。Groq、xAI、Mistral、DeepSeek、OpenRouter、Cerebras、Together、DeepInfra、Perplexity、Venice 及其他兼容网关继续进入共享协议，保留现有端点、认证、组织头、传输及请求参数约定。
- OpenRouter 保留官方主机限定的缓存字段，兼容网关不获得该字段；Go 辅助调用保留原会话/客户端标识。
- Cohere 默认兼容地址走 Chat Completions；明确选择其 native API 才走 scribe-cohere。Vercel、AIHubMix、Salad、Merge、QVAC、Cloudflare AI Gateway 的既有统一兼容配置仍优先，不强制使用目录中每个模型的原生包覆盖。
- Watsonx 保留 IBM IAM 表单换票及 /ml/v1/text/chat_stream 转发，请求协议共享 Chat Completions。现有工厂测试验证认证与文字请求；没有把 IBM 专用认证入口逐条冒充为新增 A02 账户实测。
- Vertex 的 Google、Anthropic、Mistral、OpenAI-compatible 模型级覆盖保留；后两者共享兼容消息协议和原有 Vertex 认证传输。其覆盖证据分布在工厂、连接转换及传输测试，没有把共享协议测试误写为每个真实 Vertex 模型均实测。
- legacy 无 providerNpm 的 13 个 ChatModelProviders 映射仍存在：OpenAI、Anthropic、Google、OpenRouter、Ollama、LM Studio、OpenAI-format、Cohere legacy-compatible、xAI、Groq、Mistral、DeepSeek、SiliconFlow。旧 LM Studio 默认 Responses（显式关闭后 Completions）。新本地连接 Ollama/LM Studio 与自定义地址按保存的连接协议进入同一工厂。
- `nativeModels.test.ts` 直接覆盖 manually-entered、reasoning-model、untagged-model；即使目录无工具标签或 toolCall=false，也不自动排除。运行时真实端点若拒绝工具，错误保留，不另选模型、不改用另一把密钥或静默退回文字聊天。
- 下方清单逐项抄录仓库目录夹具的所有 235 个供应商、292 个模型记录；Azure、Azure Cognitive Services、Amazon Bedrock 共 3 个供应商在已有转换器中被排除，故原测试确认可见供应商为 232。目录含语音、嵌入等非聊天条目，列出它们仅用于核对数据源完整性，不宣称都可加入聊天。模型名称是该固定夹具记录，不是联网更新后的供应商承诺。

## 明确关闭思考的补充修复

原生聊天把“沿用默认”与“明确关闭”分别保存为 null 和 off。仅对原本报告强度选项的模型增加 Default 选择，不改变共享选择器或 Quick 工具。初次未选择和恢复 Default 都保留供应商原有默认；明确关闭才在下一次请求和压缩请求中写入本协议的关闭字段。切换与重启存储保留这一区别，目录未提供关闭选项时不额外伪造该能力。

关闭语义依据固定 Pi 源码及官方文档：[OpenAI 推理控制](https://developers.openai.com/api/docs/guides/reasoning)、[Anthropic thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)、[Google thinking budget](https://ai.google.dev/gemini-api/docs/generate-content/thinking)、[Cohere disabled thinking](https://docs.cohere.com/docs/reasoning)、[Ollama think=false](https://docs.ollama.com/capabilities/thinking)、[OpenRouter reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)。自定义端点拒绝声明的参数时保留错误，不静默改用另一模型。
